# Decisions

ADR-style log. Each entry: context, decision, consequences. Deviations from
BUILD_PLAN.md are marked **(deviation)**.

## D-001 Engine: reactor (Option B) preferred, CLI (Option A) as fallback

**Context.** §5.3 offers Option A (the `hledger` executable as a WASI command,
re-instantiated per call) or Option B (a reactor module with hledger-lib
bindings that keeps the parsed journal in memory). Measurements on the
791-transaction fixture are in [ENGINE.md](ENGINE.md).

**Decision (revised).** The app prefers Option B, built in this repository
(`engine/hledger-wasm`), and keeps Option A as an automatic fallback. Option B
meets every hard limit (warm balance sheet 380–410 ms on 791 transactions) but
not the 150 ms target, because hledger's JSON pretty-printer dominates; using
text/CSV output or upstreaming compact JSON are the remaining levers, and
both are deferred so hledger stays unmodified.

**Original decision.** Ship Option A first. It is exact (85/85 goldens byte-identical to
native hledger 1.52.4), small enough (2.83 MiB brotli, 4.2 MiB gzip),
cold-starts within target, and every hledger command is available, which the
console, checks and CSV import rely on. The engine sits behind
`EngineBackend` (`run(argv)`), so Option B replaces one class.

**Consequences.** Warm reports on large journals miss the §5.4 hard limit
(balance sheet ≈ 860 ms vs 500 ms on 791 transactions; 110–270 ms on the
demo). Mitigations: per-revision result cache, `load()` = `print -O json`
(one parse gives validation *and* the transaction list), payees derived from
that result (D-008), views only query what they display. Option B is being
built (`engine/hledger-wasm`, `engine.yml`); switch when its goldens pass.

## D-002 Engine artifact provenance **(deviation)**

**Context.** §5.1 says the artifact is a GitHub Release asset of this
repository, produced by `engine.yml`. This session could not create releases
or run the multi-hour GHC toolchain build in CI.

**Decision.** `engine/wasm.lock` pins the hledger-anywhere `wasm-v2` asset
(hledger 1.52.4, GHC 9.12, unmodified upstream source, GPL-3.0) by URL **and
sha256**; `fetch.sh` refuses any other bytes. `engine.yml` reproduces the
build for this repository; the first run that publishes our own asset updates
the lock file.

## D-003 Charts: hand-rolled SVG

Three small Svelte components (`BarChart`, `LineChart`, `RankBars`, ~6 KB gzip
together) instead of a chart library. Categorical palette validated with the
dataviz validator in light and dark (6 slots, ΔE ≥ 8.7 adjacent under CVD);
every chart has a hover/tap tooltip, a legend for ≥2 series and a table view.
A donut was rejected in favour of ranked bars (readable on phones, direct
labels).

## D-004 CSP `connect-src`

Explicit list: `'self'`, `api.dropboxapi.com`, `content.dropboxapi.com`,
`api.github.com`, the build-time git proxy origin (`PUBLIC_GIT_PROXY`), plus
`PUBLIC_CSP_CONNECT_EXTRA`. A self-hosted proxy therefore needs those build
variables (or a fork's Pages deploy); we chose that over `https:` to keep
the policy strict (§2, §11). GitHub Pages can't send headers, so the policy
is a `<meta>` tag generated by Astro with hashes for its inline scripts and
styles; `'wasm-unsafe-eval'` allows compiling the engine.

## D-005 Routing

Hash routes (`#/accounts`, `#/account/assets:checking`) — static hosting
needs no rewrites, and the service worker serves one app page.

## D-006 Storage & sync port (renames vs Mycelium)

Raw IndexedDB (`IdbVaultStore`, DB `pocketledger`) instead of Dexie;
`syncFolder()` → `VaultSyncEngine`; merge base and pending-upload flags live
on `StoredFile` (`base`, `baseRev`, `dirty`, `deleted`) instead of a separate
table; tokens in a `secrets` object store; `TabLink` → `TabCoordinator`;
the worker is reduced to the git CORS proxy and GitHub OAuth exchange. Full
table in [SYNC.md](SYNC.md). Contract additions (optional, non-breaking):
`VaultStore.updateFile`, `SyncProvider.caseInsensitive` /
`maxConcurrentWrites`, `FileConflict.remoteRev`.

## D-007 Sync strategy

- **Dropbox**: automatic (debounced after save, on reconnect, periodic),
  three-way line merge against the stored base; appends on both sides are
  both kept.
- **GitHub "Direct"** (REST Contents API, no proxy): built — §8.3 left it
  open. Automatic like Dropbox; every upload is a commit. This is the default
  while no proxy is deployed.
- **GitHub "Git"** (isomorphic-git through the CORS proxy): explicit commit,
  pull, push.
- **Folder on disk** (File System Access, Chromium): writes changed files
  back on save.
- After any merge, hledger validates the vault (§8.4); a failing merge pauses
  uploads and marks the vault conflicted.

## D-008 Payees derived from transactions

hledger's payee is the description before `|` unless a `payee:` tag says
otherwise. With Option A every extra command is a full re-parse, so the app
applies that rule to the `print` result rather than running `hledger payees`.
Accounts (with types) and commodities still come from hledger.

## D-009 Contract change: `StatementSection.increasesTotal`

The third element of hledger's `cbrSubreports` is "added to / subtracted
from the net total" (Assets/Revenues true, Liabilities/Expenses false), not a
sign convention. Renamed from `normallyPositive`; amounts are already in
normal sign in hledger's JSON.

## D-010 Engine invocations use `--no-conf`

A `hledger.conf` in the vault could change report shapes the decoders
depend on (e.g. default `--tree`), so every invocation passes `--no-conf`.

## D-011 Demo data

Generated by `scripts/make-demo.mjs`, anchored at 2026-10 and shifted by whole
months to the current month at load; transactions after today are dropped so
the current month is realistically partial.

## D-012 Display of amounts

Amounts are formatted in JS from hledger's `astyle` (side, spacing, decimal
mark, digit groups, precision); lots of one commodity with different costs
are summed for display, as hledger's own balance output does. Arithmetic uses
decimal.js-light; floats are used only to draw charts.

## D-013 Reconciliation marks transactions cleared

Ticked postings clear their whole transaction (`*` in the header), the common
plain-text-accounting workflow, and optionally a zero-amount posting with a
balance assertion is appended on the statement date.

## D-014 Goldens stored gzip-compressed

`tests/golden/expected/*.out.gz` (450 KB instead of 6.4 MB).

## D-015 Hosting the reactor artifact **(deviation)**

The reactor `.wasm` and its JSFFI glue are pinned by sha256 in
`engine/wasm.lock` but `reactor_url` is empty: no release asset exists yet.
`fetch.sh` uses a verified local build (`engine/artifacts/`) or the URL once
`engine.yml` has published one, and otherwise leaves the reactor out, in which
case the build ships the CLI engine only. The artifact is deliberately not
committed to git (13 MB per version).

## D-016 Writer contract clarifications

From the writer port: `PostingDraft.commodity` `undefined` = default
commodity, `''` = none; lots live in `cost` with the price; `append` text is
verbatim, `insert` text has no trailing EOL; `planEdit` may return `[]`;
`JournalStyle.commodities` (optional) carries per-commodity styles. New
negative left-side amounts are written `$-12.50`, as `hledger print` does.
